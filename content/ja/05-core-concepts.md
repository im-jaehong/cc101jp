# 07. コアコンセプトを理解する

> Claude Codeがどのように動作するかを知ると、より上手に使えるようになります。

---

## Claude Codeはどのように動作するのか？

Claude Codeは単なるチャットボットではありません。指示を出すと、自ら計画を立て、ファイルを読み、コードを修正し、結果を確認する**エージェント（Agent）**です。

このプロセスを**エージェントループ（Agentic Loop）**と呼びます。

```
あなたの指示
     ↓
1. 状況把握（Context収集）
   - ファイル読み込み、コード検索、現在の状態把握
     ↓
2. 行動（Action）
   - ファイル修正、コマンド実行、Web検索
     ↓
3. 結果確認（Verify）
   - テスト実行、エラー確認、再修正
     ↓
作業完了（または1に戻って繰り返し）
```

例えば「reports/ フォルダのドキュメントを要約して」と言うと、Claude Codeは：
1. フォルダ内のファイル一覧を確認
2. 各ドキュメントを読んで内容を把握
3. 要約・整理を作成
4. 結果を確認し、不足があれば補完

この全プロセスを**自動的に**実行します。

<details>
<summary>🖥️ 開発者向けの例（バグ修正）</summary>

「テストが失敗するバグを直して」と言うと：
1. テストを実行してどんなエラーか確認
2. 関連するソースファイルを探して読む
3. コードを修正
4. 再度テストを実行して通るか確認

</details>

## 5つのコアコンセプト

### 1. Context（コンテキスト） — Claudeの作業記憶

**コンテキスト**とは、Claude Codeが現在記憶しているすべての内容です。会話内容、読んだファイル、実行したコマンドの結果、CLAUDE.mdの指示事項など、すべてがコンテキストに含まれます。

コンテキストには**トークンの上限**があります（現在のモデルはすべて100万トークン）。会話が長くなったり、大きなファイルを多く読んだりすると、コンテキストがいっぱいになることがあります。上限に近づくと、Claude Codeが自動的に古い内容を要約します（自動圧縮）。

```
# コンテキストの状況確認
/context

# 会話の圧縮（古い内容を要約）
/compact

# 特定のテーマに集中して圧縮
/compact API変更点に集中して圧縮して
```

> **ヒント**：頻繁に参照する重要なルールや情報はCLAUDE.mdに書いておくと、毎回コンテキストを消費せずにClaudeが記憶できます。

---

### 2. Tools（ツール） — Claudeが実際にできること

Claude Codeは会話するだけではありません。実際に様々な**ツール（Tools）**を使って作業を実行します。

| ツールの種類 | Claudeができること |
|----------|----------------------|
| **ファイル操作** | ファイル読み込み、コード編集、新規ファイル作成、ファイル名変更 |
| **検索** | ファイルパターンで検索、正規表現で内容検索、コードベース探索 |
| **実行** | シェルコマンド実行、サーバー起動、テスト実行、Git操作 |
| **Web** | Web検索、公式ドキュメント参照、エラーメッセージ検索 |
| **コード分析** | 編集後の型エラー検出、定義へのジャンプ、参照の検索 |
| **委任** | サブエージェント（もう一人のClaude）に探索・検証のような付随タスクを任せ、結果だけ受け取る |

---

### 3. Permissions（権限） — 何を許可するか設定する

Claude Codeは強力なツールであるため、**何を許可するかを直接制御**できます。

ファイルの読み込みはデフォルトで許可されていますが、ファイルの修正やシェルコマンドの実行はユーザーの確認を求めます。

権限ルールは大きく3種類です：

| ルール | 説明 |
|------|------|
| **Allow（許可）** | 確認なしで自動的に実行 |
| **Ask（確認要求）** | 実行前に承認を求める |
| **Deny（拒否）** | 絶対に実行しない |

```
# 権限設定の確認と管理
/permissions
```

> **優先順位**：Deny > Ask > Allow の順に適用されます。拒否ルールが常に最優先です。

---

### 4. Memory（メモリ） — CLAUDE.mdでプロジェクトを記憶させる

Claude Codeはセッションが終わると会話内容を記憶しません。しかし**CLAUDE.md**ファイルを作っておくと、毎セッション自動的に読み込んでプロジェクトのコンテキストを維持します。

CLAUDE.mdはClaudeに渡す**指示書**だと考えてください。

| ファイルの場所 | 適用範囲 |
|----------|---------|
| `./CLAUDE.md` | 現在のプロジェクトのみ適用（チーム共有可能） |
| `~/.claude/CLAUDE.md` | すべてのプロジェクトに適用（グローバル設定） |
| `./CLAUDE.local.md` | 自分だけのプロジェクト別設定（`.gitignore`に追加してアップしない） |
| `.claude/rules/*.md` | テーマ別に分けたルールファイル（特定のファイルパスにだけ適用されるよう制限可能） |

これに加えて**自動メモリ（auto memory）**があります。あなたが修正した内容や好みをClaudeが自らメモしておき、次のセッションで再び読み込む機能で、デフォルトで有効です。`/memory` でメモの内容を見たり、オフにしたりできます。

> CLAUDE.mdの詳細については**[08. CLAUDE.md 詳細ガイド](./06-claude-md.md)**で解説します。

---

### 5. Session（セッション） — 会話の始まりと終わり

**セッション**とは、Claude Codeを起動してから終了するまでの1つの作業単位です。

- 新しいセッションを開始すると、以前の会話内容はなくなります（CLAUDE.mdは維持）
- セッション中に行った作業は保存されます

```bash
# 最新のセッションを引き継いで開始
claude --continue

# 以前のセッション一覧から選んで再開
claude --resume

# 最初から名前を付けて開始（後で claude --resume 名前 で再開）
claude -n 競合調査

# 別の方向を試すためにセッションを複製（フォーク）
claude --continue --fork-session
```

会話の途中では `/rename 名前` で名前を付けたり、`/branch` で現在の地点から会話を分岐したりできます。

## 「なぜ時々止まって確認を求めるのですか？」

Claude Codeが作業中に止まって確認を求めるのは、**意図された安全装置**です。

ファイルを修正したりコマンドを実行する前に、ユーザーが意図した操作かどうか確認しているのです。特に元に戻しにくい操作（ファイル削除、デプロイなど）ほど重要です。

---

## 初心者が知っておくべき4つの権限モード

`Shift+Tab` を押すと権限モードを切り替えることができます。プロンプト下のステータスバーに `auto mode on`、`manual mode on` のように現在のモードが表示されます。

| モード | 画面表示 | 動作方式 | いつ使うか |
|------|----------|----------|------------|
| **Auto（自動）** | `⏵⏵ auto mode on` | 別の検査モデル（分類器）がバックグラウンドで各行動を審査し、危険でなければ確認なしで実行。**新しいセッションのデフォルト開始モード** | 長い作業、確認ダイアログ疲れを減らしたいとき |
| **Manual（手動）** | `⏸ manual mode on` | ファイル修正とシェルコマンド実行前に毎回確認を要求（設定値の名前は`default`） | Claudeが何をしているか自分の目で見たいとき、慎重を要する作業 |
| **Accept Edits（編集自動承認）** | `⏵⏵ accept edits on` | ファイル修正と `mkdir`、`mv` のような基本的なファイルコマンドは自動許可、それ以外のシェルコマンドは確認要求 | 自分がレビュー中のコードを素早く直すとき |
| **Plan Mode（計画モード）** | `⏸ plan mode on` | ファイルを読んで分析するだけで、何も修正しない | まず計画を確認したいとき |

> **補足（2026年10月時点）**：Claude Code **v2.1.283から、ターミナルセッションはすべてのプランでAutoモードで開始**します。Autoモードは「何も聞かないモード」ではなく、人の代わりに分類器が審査するモードです。リクエストの範囲を外れる行動、見慣れないサーバーへのアクセス、読み込んだ外部コンテンツに引きずられた行動はブロックし、それでも判断が難しい場合はあなたに確認します。安全を保証する仕組みではないので、慎重を要する作業はManualモードに切り替えて自分で確認してください。
>
> モデルがAutoモードに対応していない場合や、組織の設定でオフになっている場合はManualモードで開始します。

### モード切り替え方法

```
# ターミナルでShift+Tabを押すとモードが順番に切り替わります
# Auto → Manual → Accept Edits → Plan Mode → Auto → ...

# またはPlan Modeに直接切り替え（説明を付けると、その作業の計画からすぐ開始）
/plan
/plan 認証システムをOAuth2に切り替える計画を立てて

# 最初から特定のモードで開始
claude --permission-mode plan
claude --permission-mode manual
```

> シェルコマンドの確認ダイアログに **"Yes, and switch to auto mode"** という選択肢が表示されたら、そのコマンドを許可すると同時にAutoモードへ切り替えるという意味です。

### モード比較の例

```
「フォルダ内のドキュメントで『旧バージョンの文言』を『新しい文言』に一括置換して」と言った場合：

Autoモード：
  → 分類器が「リクエストの範囲内の安全な作業」と判断すればすぐ実行
  → リクエストと無関係なフォルダを削除しようとしたらブロック

Manualモード：
  → 各ファイルの修正前に「このファイルを修正してもいいですか？」と確認

Accept Editsモード：
  → ファイルは自動で修正、コマンド実行は確認要求

Plan Mode：
  → 「どのファイルのどの部分を変更する予定です」と表示するだけで、実際の修正はしない
```

<details>
<summary>🖥️ 開発者向けの例</summary>

```
「すべてのJavaScriptファイルからconsole.logを削除して」と言った場合：

Autoモード：
  → ファイル修正とテスト実行はそのまま進行、`git push --force` のような行動はブロックまたは確認

Manualモード：
  → 各ファイルの修正前に「このファイルを修正してもいいですか？」と確認

Accept Editsモード：
  → ファイルは自動で修正、コマンド（例：git commit）は確認要求

Plan Mode：
  → 「どのファイルの何行目を修正する予定です」と表示するだけで、実際の修正はしない
```

</details>

> **おすすめ**：最初の数日は `Shift+Tab` で**Manualモード**に切り替え、Claude Codeが何をしているかを自分の目で見ながら慣れていきましょう。流れがつかめたらデフォルトの**Autoモード**に戻し、決済・デプロイ・削除のように元に戻しにくい作業だけManualに切り替えれば十分です。
>
> どのモードでも、`.git`、`.claude` のような保護パスの変更や、ホームフォルダ・ルートを消す `rm -rf` のような致命的なコマンドは自動承認されません。

## チェックポイント：ミスしても元に戻せます

Claude Codeはファイルを修正する前に**自動でスナップショット**を保存します。

誤って修正してしまった場合：
- 入力欄が空の状態で `Esc` キーを2回連続で押すか、`/rewind` と入力すると巻き戻しメニューが開きます。コードだけ、会話だけ、または両方を以前の地点に戻せます。
- またはClaudeに「今やったことを取り消して」とリクエスト

> 巻き戻しは、Claudeが編集ツールで修正したファイルだけを追跡します。`rm`、`mv` のようなシェルコマンドで変更されたファイルは戻せないので、大きな作業の前にはgitコミットも合わせて行っておきましょう。
