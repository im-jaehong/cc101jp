# 19. コスト管理 & 節約のヒント

> Claude Codeをよりスマートに、より安く使う方法を学びます。

---

## コスト構造の概要

Claude Codeの料金体系は大きく2種類あります。

| 区分 | 方式 | 特徴 |
|------|------|------|
| **Claude.ai Pro / Max** | 定額制サブスクリプション | 月額固定料金、API費用は別途不要 |
| **Anthropic API** | 従量制 | 使用したトークン数に応じて料金が発生 |

**Claude.ai Pro/Maxサブスクリプション利用者**は、サブスクリプション料金にClaude Codeの利用が含まれているため、API費用は別途請求されません。`/usage`（`/cost`はエイリアス）が表示するドル金額はAPIユーザー向けのものなので、サブスクリプション利用者は参考程度にご覧ください。同じ画面でプラン使用量のバーを確認できます。

**APIユーザー**は使用量に応じて料金が発生します。公式ドキュメント（2026年10月時点）によると、平均して開発者1人あたり**利用日1日約$13、月$150〜$250**で、90%のユーザーは1日$30以下です。

サブスクリプション利用者も、プランの上限を使い切ったら**追加使用量（usage credits）** をオンにして従量制で使い続けることができます。`/usage-credits`で設定ページが開き、月の支出上限を決めておくことができます。

## トークンとは？

**トークン(token)**はClaudeがテキストを処理する単位です。

- 英語の場合：約1単語 = 1〜2トークン
- 日本語の場合：約1〜2文字 = 1トークン
- 大まかに：**英語4文字 ≈ 1トークン**

簡単に言えば、Claudeにファイルを読ませたり、質問したり、回答を受け取るたびにトークンが消費されます。コンテキスト（会話の文脈）が長くなるほど、より多くのトークンが使用されます。

---

## コストが高くなる状況

### 1. 長いファイルを繰り返し読む場合

Claudeが同じファイルを何度も読むと、そのたびにトークンが消費されます。10,000行のログファイルをまるごと読ませると、1回で数万トークンが使用されます。

### 2. コンテキストを長時間維持する場合

会話が長くなるほど、以前の内容をすべてコンテキストに含める必要があります。関連のない作業を同じセッションで続けると、不要な情報が蓄積されコストが増加します。

### 3. 高性能モデル・高い思考強度を使用する場合

OpusモデルはSonnetより強力ですが、トークンあたりのコストも高くなります。簡単な作業にOpusを使うのは非効率的です。思考強度（`/effort`）を`xhigh`や`max`に上げると、考えるためのトークン（出力トークンとして課金）もその分増えます。

### 4. 自動化（CI/CD）で無制限に実行する場合

GitHub Actionsなどで自動化すると、人の介入なしに大量のトークンが消費される可能性があります。

## 節約のヒント5選

### ヒント1：`/compact`でコンテキストを整理する

会話が長くなったとき、`/compact`コマンドを実行すると、以前の内容を要約してコンテキストサイズを削減してくれます。

```
/compact コード変更とテスト結果を中心に要約して
```

これにより重要な情報は維持しながら、不要な会話内容が圧縮されます。

CLAUDE.mdに圧縮方法をあらかじめ指定することもできます：

```markdown
# Compact instructions

When you are using compact, please focus on test output and code changes
```

> **ヒント**：`/clear`を使うとコンテキストを完全にリセットできます。まったく別の作業を始めるときに便利です。

---

### ヒント2：不要なファイル参照を避ける

曖昧なリクエストは、Claudeに不必要に多くのファイルを読ませてしまいます。

| 非効率的なリクエスト | 効率的なリクエスト |
|----------------|--------------|
| 「このコードベースを改善して」 | 「auth.tsのlogin関数に入力バリデーションを追加して」 |
| 「バグを探して」 | 「セッション期限切れ後にログインが失敗する問題をsrc/auth/で確認して」 |

具体的なリクエストほど、Claudeが必要なファイルだけを読むためトークン消費が減ります。

---

### ヒント3：Haikuモデルを活用する

すべての作業に高性能モデルを使う必要はありません。

| モデル | 用途 | コスト |
|------|------|------|
| **Haiku 5.5** | 簡単な質問、ファイル要約、単純な作業、サブエージェント | 非常に低い（Opusの1/40） |
| **Sonnet 5.5** | 一般的なコーディング・ドキュメント作業 | 中程度（Opusの1/2） |
| **Opus 5.5** | 複雑な設計、難しい推論 — すべてのプランのデフォルトモデル | 高い |
| **Fable 5.1** | 最難関・長時間の自律作業（別途アクセス権が必要） | 非常に高い |

モデルの切り替えはセッション中でも可能です：

```
/model haiku
```

または起動時に指定：

```bash
claude --model haiku
```

**`opusplan`モード**：計画段階ではOpus、実行段階ではSonnetに自動で切り替わるハイブリッドモードです。

```
/model opusplan
```

**思考強度を下げる**：モデルを変えなくても、`/effort low`または`/effort medium`で考える量を減らせます。Opus 5.5 / Sonnet 5.5 / Haiku 5.5のデフォルトは`medium`で、単純な繰り返し作業なら`low`でも十分な場合が多いです。（これらのモデルは拡張思考を完全にオフにすることはできず、強度だけを調節します。）

---

### ヒント4：Fast Modeを理解して活用する

`/fast`コマンドでFast Modeをオンにすると、Opusが最大2.5倍速く応答します。現在は**Opus 5.5、Opus 5、Opus 4.8**で利用できます（Claude Code v2.1.280以降はOpus 5.5がデフォルト）。Sonnet、Haikuでは使えません。

```
/fast
```

ただし、Fast Modeは**トークンあたりのコストが高くなります**（Opus 5.5の場合、入力$8 / 出力$40 per MTok＝通常のOpus 5.5の2倍）。速度が重要な場面（素早い反復作業、リアルタイムデバッグ）でのみ使用し、長時間の自律作業ではオフにするのがおすすめです。オンになっているとプロンプトの横に`↯`アイコンが表示され、`/fast`をもう一度入力すると、現在のオン/オフ状態を確認できます。会話の途中でオンにすると、その時点までのコンテキスト全体をFast Mode料金で一度読み直すため、使うならセッション開始時にオンにする方が安く済みます。

> **注意**：Fast Modeはサブスクリプションプランの基本使用量には含まれず、**追加使用量（usage credits）** から差し引かれます。追加使用量をオンにしていない状態では、`/fast`が「Fast mode requires usage credits」と案内します。まだ研究プレビュー段階のため、価格や条件が変わる可能性があります。

---

### ヒント5：`/usage`で定期的に確認する

現在のセッションのトークン使用量を確認できます（`/cost`は同じコマンドのエイリアス）：

```
/usage
```

出力例：
```
Total cost:            $0.55
Total duration (API):  6m 19.7s
Total duration (wall): 6h 33m 10.2s
Total code changes:    0 lines added, 0 lines removed
```

サブスクリプション利用者は同じ画面でプラン使用量のバーと使用先の分析（スキル・サブエージェント・プラグイン・MCPサーバー別の割合、長いコンテキストやキャッシュミスのような使用量を増やす習慣）を確認できます。`/stats`は同じ画面の統計タブを直接開きます。

ステータスバー（status line）を設定すると、コンテキスト使用量をリアルタイムで確認することもできます（`/statusline`）。トークン数ではなく「どう使っているか」が知りたいときは、`/insights`で最近のセッションの分析レポートを作成できます。

> **長いセッションは静かに高くつきます。** 1行の質問でも、リクエストのたびに会話全体を送り直すからです。1時間以上休んでから戻るとキャッシュが期限切れになり、コンテキスト全体を再処理するため、Pro/Maxでは大きなセッションを再開するときに「要約から再開するか」を尋ねるダイアログが表示されます。作業が終わったなら`/clear`、続けるなら`/compact`が正解です。

---

### ヒント6：CLAUDE.mdをダイエットする

CLAUDE.mdはClaudeが**毎回の応答ごとに**読むファイルです。長ければ長いほど、毎回より多くのトークンを消費します。

**実際の効果**：過度に記述されたCLAUDE.md（約19,000トークン）を要点だけ残したバージョン（約9,000トークン）に整理すると、同じ作業にかかるコストがほぼ半分に減ります。

**ダイエットの基準**

```
削除してよいもの：
- 長い背景説明（「このプロジェクトは2023年から...」）
- 繰り返される当たり前の内容（「常にベストを尽くしてください」）
- 複数のサンプルコードブロック（1つだけ残すか削除）
- 曖昧なルール（「良いコードを書いてください」）

必ず残すもの：
- 禁止事項（絶対にやってはいけないこと）
- プロジェクトの技術スタック（1〜3行の要約）
- よく参照するファイルパス
- 言語/フォーマットのルール（具体的なもののみ）
```

ほとんどのCLAUDE.mdは整理すると50%以上削減できます。

---

### ヒント7：権限のdenyルールで不要なファイルを除外する

`node_modules`、ビルド成果物、`.env`などをClaudeが読まないようにすると、誤って大容量ファイルや秘密情報を読み込むのを防げます。

> ⚠️ **`.claudeignore`ファイルはClaude Codeに読み込まれません。** ネット上で広まっている方法ですが、実際には効果がありません。代わりにプロジェクトの`.claude/settings.json`に**権限のdenyルール**を書いてください。

```json
// .claude/settings.json
{
  "permissions": {
    "deny": [
      "Read(node_modules/**)",
      "Read(dist/**)",
      "Read(build/**)",
      "Read(coverage/**)",
      "Read(**/*.log)",
      "Read(.env)",
      "Read(.env.*)"
    ]
  }
}
```

> `Read`のdenyルールはEditツールや、Claude Codeが認識する`cat`・`head`などのBashファイルコマンドにも適用されます。ただしPythonやNodeのスクリプトが直接ファイルを開く場合までは防げないため、OSレベルの遮断が必要ならサンドボックスを使ってください。

**特に効果的な場面**
- モノレポのようにファイル数が多いプロジェクト
- 「このプロジェクト全体を分析して」というリクエストを頻繁に行う場合
- GitHub Actionsなどで Claudeを繰り返し実行する場合

## モデル別コスト比較（概要）

（2026年10月時点のAPI定価、100万トークンあたり 入力 / 出力）

| モデル | 特徴 | コンテキスト | 入力 / 出力 |
|------|------|--------------|-------------|
| Haiku 5.5 | 最速・最安、簡単な作業・サブエージェント | 1M | $0.10 / $0.50（プロンプト10万トークン超過分は $0.50 / $2.50） |
| Sonnet 5.5 | 速度と知能のバランス、一般的なコーディング作業 | 1M | $2 / $10 |
| Opus 5.5 | 複雑なエージェント的コーディング・推論（デフォルトモデル） | 1M | $4 / $20 |
| Fable 5.1 | 最難関・長時間の自律作業 | 1M | $10 / $50 |
| Opus 5.5 (Fast Mode) | Opus 5.5の最大2.5倍速 | 1M | $8 / $40 |

> 前世代（Opus 5 $5/$25、Sonnet 5 $2/$10、Haiku 4.5 $1/$5、200K）も引き続き使えますが、エイリアス（`opus`、`sonnet`、`haiku`）はすべて5.5世代を指します。
> 最新の正確な価格は[Anthropic料金ページ](https://claude.com/pricing)と[API料金ドキュメント](https://platform.claude.com/docs/en/about-claude/pricing)をご参照ください。

## Claude.ai Maxプランのメリット

Claude.ai ProまたはMaxサブスクリプション利用者は、**API従量制の費用なしで**Claude Codeを使用できます。

- 月額料金にClaude Codeの使用が含まれる
- 追加のAPIキーが不要
- コストを気にせず様々な実験が可能
- Maxプランの場合、より高い使用量上限

> **ただし、Fast Modeはサブスクリプションの上限とは別に追加使用量（usage credits）から差し引かれます。** プランの上限（5時間単位・週単位でリセット）を超えたら、リセットを待つか、`/usage-credits`で追加使用量をオンにして使い続けることができます。

## チームのコスト管理

APIをチーム単位で使用する場合：

- **Workspaceの支出上限を設定**：[Anthropic Console](https://platform.claude.com)でチーム全体の支出上限を設定できます。
- **使用量ダッシュボード**：Consoleでメンバーごとのコストと使用量を確認できます。
- **エージェントチームに注意**：Agent Teams（複数のClaudeインスタンスを同時実行）機能は、標準セッションの約7倍のトークンを消費します。現在は**実験的機能でデフォルトは無効**であり、`settings.json`に`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`を設定すると有効になります。

## まとめ：コスト節約チェックリスト

```
✅ 作業が終わったら/clearでコンテキストをリセット
✅ 関連のない作業は新しいセッションで開始
✅ 具体的なファイル名と関数名を明示
✅ 簡単な作業にはHaikuモデルを使用、または /effort low・medium で思考強度を下げる
✅ Fast Modeは必要なときだけオンにする（追加使用量から差し引き）
✅ /usage（= /cost）で定期的に確認
✅ CLAUDE.mdにcompact指示を設定
✅ CLAUDE.mdは重要なルールだけ残して定期的にダイエット
✅ permissions.denyのReadルールでnode_modules、ビルド成果物、.envを除外
```
