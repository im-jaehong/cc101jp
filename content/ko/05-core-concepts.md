# 07. 핵심 개념 이해하기

> Claude Code가 어떻게 작동하는지 알면, 더 잘 사용할 수 있습니다.

---

## Claude Code는 어떻게 작동하나요?

Claude Code는 단순한 챗봇이 아닙니다. 여러분이 일을 시키면, 스스로 계획을 세우고, 파일을 읽고, 코드를 수정하고, 결과를 확인하는 **에이전트(Agent)** 입니다.

이 과정을 **에이전트 루프(Agentic Loop)** 라고 합니다.

```
여러분의 지시
     ↓
1. 상황 파악 (Context 수집)
   - 파일 읽기, 코드 검색, 현재 상태 파악
     ↓
2. 행동 (Action)
   - 파일 수정, 명령어 실행, 웹 검색
     ↓
3. 결과 확인 (Verify)
   - 테스트 실행, 오류 확인, 다시 수정
     ↓
작업 완료 (또는 1로 돌아가서 반복)
```

예를 들어 "reports/ 폴더 문서를 요약해줘"라고 하면 Claude Code는:
1. 폴더 안의 파일 목록을 확인
2. 각 문서를 읽어 내용 파악
3. 요약 및 정리 작성
4. 결과를 확인하고 빠진 내용이 있으면 다시 보완

이 모든 과정을 **자동으로** 수행합니다.

<summary>🖥️ 개발자 예시 (버그 수정)</summary>

"테스트가 실패하는 버그를 고쳐줘"라고 하면:
1. 테스트를 실행해서 어떤 오류인지 확인
2. 관련 소스 파일을 찾아서 읽음
3. 코드를 수정
4. 다시 테스트를 실행해서 통과하는지 확인

</details>

## 핵심 개념 5가지

### 1. Context (컨텍스트) — Claude의 작업 기억

**컨텍스트**는 Claude Code가 현재 기억하고 있는 모든 내용입니다. 대화 내용, 읽은 파일, 실행한 명령어 결과, CLAUDE.md 지시사항 등이 모두 컨텍스트에 담깁니다.

컨텍스트에는 **토큰 한계**가 있습니다 (현재 모델은 모두 100만 토큰). 대화가 길어지거나 큰 파일을 많이 읽으면 컨텍스트가 가득 찰 수 있습니다. 한계에 가까워지면 Claude Code가 자동으로 오래된 내용을 요약(자동 압축)합니다.

```
# 컨텍스트 현황 확인
/context

# 대화 압축 (오래된 내용 요약)
/compact

# 특정 주제에 집중해서 압축
/compact API 변경 사항에 집중해서 압축해줘
```

> **팁**: 자주 참조해야 할 중요한 규칙이나 정보는 CLAUDE.md에 써두면, 매번 컨텍스트를 차지하지 않고도 Claude가 기억합니다.

---

### 2. Tools (도구) — Claude가 실제로 할 수 있는 일

Claude Code는 대화만 하는 게 아닙니다. 실제로 여러 **도구(Tools)**를 사용해서 작업을 수행합니다.

| 도구 종류 | Claude가 할 수 있는 일 |
|----------|----------------------|
| **파일 작업** | 파일 읽기, 코드 편집, 새 파일 생성, 파일 이름 변경 |
| **검색** | 파일 패턴으로 찾기, 정규식으로 내용 검색, 코드베이스 탐색 |
| **실행** | 셸 명령어 실행, 서버 시작, 테스트 실행, Git 사용 |
| **웹** | 웹 검색, 공식 문서 조회, 오류 메시지 검색 |
| **코드 분석** | 편집 후 타입 오류 감지, 정의로 이동, 참조 찾기 |
| **위임** | 서브에이전트(또 다른 Claude)에게 탐색·검증 같은 곁가지 작업을 맡기고 결과만 받기 |

---

### 3. Permissions (권한) — 무엇을 허용할지 설정

Claude Code는 강력한 도구인 만큼, **무엇을 허용할지 직접 제어**할 수 있습니다.

파일 읽기는 기본적으로 허용되지만, 파일 수정이나 셸 명령어 실행은 여러분의 확인을 요청합니다.

권한 규칙은 크게 세 가지입니다:

| 규칙 | 설명 |
|------|------|
| **Allow (허용)** | 묻지 않고 자동으로 실행 |
| **Ask (확인 요청)** | 실행 전에 승인 여부를 물어봄 |
| **Deny (거부)** | 절대 실행하지 않음 |

```
# 권한 설정 보기 및 관리
/permissions
```

> **우선순위**: Deny > Ask > Allow 순으로 적용됩니다. 거부 규칙이 항상 최우선입니다.

---

### 4. Memory (메모리) — CLAUDE.md로 프로젝트 기억시키기

Claude Code는 세션이 끝나면 대화 내용을 기억하지 못합니다. 하지만 **CLAUDE.md** 파일을 만들어두면, 매 세션마다 자동으로 읽어서 프로젝트 맥락을 유지합니다.

CLAUDE.md는 Claude에게 주는 **지시서**라고 생각하면 됩니다.

| 파일 위치 | 적용 범위 |
|----------|---------|
| `./CLAUDE.md` | 현재 프로젝트에만 적용 (팀 공유 가능) |
| `~/.claude/CLAUDE.md` | 내 모든 프로젝트에 적용 (전역 설정) |
| `./CLAUDE.local.md` | 나만의 프로젝트별 설정 (`.gitignore`에 추가해서 올리지 않기) |
| `.claude/rules/*.md` | 주제별로 나눈 규칙 파일 (특정 파일 경로에만 적용되도록 제한 가능) |

여기에 더해 **자동 메모리(auto memory)** 가 있습니다. 여러분이 고쳐준 내용이나 선호를 Claude가 스스로 메모해 두었다가 다음 세션에 다시 읽는 기능으로, 기본으로 켜져 있습니다. `/memory`에서 메모 내용을 보거나 끌 수 있습니다.

> CLAUDE.md에 대한 자세한 내용은 **[08. CLAUDE.md 완전 정복](./06-claude-md.md)** 에서 다룹니다.

---

### 5. Session (세션) — 대화의 시작과 끝

**세션**은 Claude Code를 시작해서 종료하기까지의 하나의 작업 단위입니다.

- 새 세션을 시작하면 이전 대화 내용은 없어집니다 (CLAUDE.md는 유지)
- 세션 중에 한 작업들은 저장됩니다

```bash
# 가장 최근 세션 이어서 시작
claude --continue

# 이전 세션 목록에서 선택해서 재개
claude --resume

# 처음부터 이름을 붙여서 시작 (나중에 claude --resume 이름 으로 재개)
claude -n 경쟁사-리서치

# 다른 방향을 시도해보기 위해 세션 복사 (포크)
claude --continue --fork-session
```

대화 도중에는 `/rename 이름`으로 이름을 붙이고, `/branch`로 현재 지점에서 대화를 분기할 수 있습니다.

## "왜 가끔 멈추거나 확인을 요청하나요?"

Claude Code가 작업 중에 멈추고 확인을 요청하는 건 **의도된 안전 장치**입니다.

파일을 수정하거나 명령어를 실행하기 전에, 여러분이 의도한 것인지 확인하는 것입니다. 특히 되돌리기 어려운 작업(파일 삭제, 배포 등)일수록 중요합니다.

---

## 초보자가 알아야 할 권한 모드 4가지

`Shift+Tab` 을 누르면 권한 모드를 전환할 수 있습니다. 프롬프트 아래 상태 표시줄에 `auto mode on`, `manual mode on`처럼 현재 모드가 표시됩니다.

| 모드 | 화면 표기 | 동작 방식 | 언제 쓰나요? |
|------|----------|----------|------------|
| **Auto (자동)** | `⏵⏵ auto mode on` | 별도의 검사 모델(분류기)이 백그라운드에서 각 행동을 검토하고, 위험하지 않으면 묻지 않고 실행. **새 세션의 기본 시작 모드** | 긴 작업, 확인 창 피로를 줄일 때 |
| **Manual (수동)** | `⏸ manual mode on` | 파일 수정과 셸 명령어 실행 전에 매번 확인을 요청 (설정값 이름은 `default`) | Claude가 무엇을 하는지 직접 보고 싶을 때, 민감한 작업 |
| **Accept Edits (편집 자동 수락)** | `⏵⏵ accept edits on` | 파일 수정과 `mkdir`, `mv` 같은 기본 파일 명령은 자동 허용, 그 외 셸 명령어는 확인 요청 | 내가 검토 중인 코드를 빠르게 고칠 때 |
| **Plan Mode (계획 모드)** | `⏸ plan mode on` | 파일을 읽고 분석만 하고, 아무것도 수정하지 않음 | 먼저 계획을 검토하고 싶을 때 |

> **참고 (2026년 10월 기준)**: Claude Code **v2.1.283부터 터미널 세션은 모든 플랜에서 Auto 모드로 시작**합니다. Auto 모드는 "묻지 않는 모드"가 아니라, 사람 대신 분류기가 검토하는 모드입니다. 요청 범위를 벗어나는 행동, 낯선 서버 접근, 읽어 들인 외부 콘텐츠에 휘둘린 행동은 차단하고, 그래도 판단이 어려우면 여러분에게 묻습니다. 안전을 보장하는 장치는 아니므로 민감한 작업은 Manual 모드로 전환해 직접 확인하세요.
>
> 모델이 Auto 모드를 지원하지 않거나 조직에서 꺼둔 경우에는 Manual 모드로 시작합니다.

### 모드 전환 방법

```
# 터미널에서 Shift+Tab을 누르면 모드가 순환됩니다
# Auto → Manual → Accept Edits → Plan Mode → Auto → ...

# 또는 Plan Mode로 바로 진입 (설명을 붙이면 그 작업의 계획부터 시작)
/plan
/plan 인증 시스템을 OAuth2로 바꾸는 계획 세워줘

# 처음부터 특정 모드로 시작
claude --permission-mode plan
claude --permission-mode manual
```

> 셸 명령어 확인 창에 **"Yes, and switch to auto mode"** 선택지가 보이면, 그 명령을 허용하면서 동시에 Auto 모드로 전환하는 것입니다.

### 모드 비교 예시

```
"폴더 내 문서에서 '구버전 문구'를 '신규 문구'로 일괄 교체해줘"라고 했을 때:

Auto 모드:
  → 분류기가 "요청 범위 안의 안전한 작업"으로 판단하면 바로 실행
  → 요청과 관계없는 폴더를 지우려 하면 차단

Manual 모드:
  → 각 파일 수정 전마다 "이 파일을 수정해도 될까요?" 확인

Accept Edits 모드:
  → 파일은 자동으로 수정, 명령어 실행은 확인 요청

Plan Mode:
  → "어떤 파일의 어느 부분을 바꿀 예정입니다"만 보여주고 실제 수정은 안 함
```

<details>
<summary>🖥️ 개발자 예시</summary>

```
"모든 JavaScript 파일에서 console.log를 삭제해줘"라고 했을 때:

Auto 모드:
  → 파일 수정과 테스트 실행은 바로 진행, `git push --force` 같은 행동은 차단 또는 확인

Manual 모드:
  → 각 파일 수정 전마다 "이 파일을 수정해도 될까요?" 확인

Accept Edits 모드:
  → 파일은 자동으로 수정, 명령어(예: git commit)는 확인 요청

Plan Mode:
  → "어떤 파일의 몇 번째 줄을 수정할 예정입니다"만 보여주고 실제 수정은 안 함
```

</details>

> **추천**: 처음 며칠은 `Shift+Tab`으로 **Manual 모드**로 바꿔 Claude Code가 무엇을 하는지 직접 보면서 익히세요. 흐름이 익숙해지면 기본값인 **Auto 모드**로 돌아가고, 결제·배포·삭제처럼 되돌리기 어려운 작업만 Manual로 전환하면 됩니다.
>
> 어떤 모드든 `.git`, `.claude` 같은 보호 경로 수정과 홈 폴더·루트를 지우는 `rm -rf` 같은 치명적 명령은 자동 승인되지 않습니다.

## 체크포인트: 실수해도 되돌릴 수 있어요

Claude Code는 파일을 수정하기 전에 **자동으로 스냅샷**을 저장합니다.

실수로 잘못 수정됐다면:
- 입력창이 비어 있는 상태에서 `Esc` 키를 두 번 연속으로 누르거나 `/rewind`를 입력하면 되감기 메뉴가 열립니다. 코드만, 대화만, 또는 둘 다 이전 지점으로 되돌릴 수 있습니다.
- 또는 Claude에게 "방금 한 것 취소해줘"라고 요청

> 되감기는 Claude가 편집 도구로 고친 파일만 추적합니다. `rm`, `mv` 같은 셸 명령으로 바뀐 파일은 되돌릴 수 없으니, 큰 작업 전에는 git 커밋을 함께 해두세요.
